Agent tools
===========

`backend/tutor/agent_tools.py` is the command-line surface used by the Hermes
agent. Each command prints exactly one JSON object on stdout —
`{"ok": true, "data": ...}` on success, `{"ok": false, "error": "..."}` on
failure — and the exit code is 0 or 1. Run from the repository root:

    python -m backend.tutor.agent_tools <commande> [arguments]

Reading
-------
- `concepts`, `profile`
- `documents <concept_id>`, `graph <concept_id>`, `mastery <concept_id>`,
  `history <concept_id>`, `errors <concept_id>`, `activity <concept_id>`

Writing
-------
The agent writes a JSON proposal under `data/agent/` and passes its path:

- `save_profile <path>`: validates the global profile (display name,
  preferences, weaknesses), merges it with the existing profile and stores
  it. The profile is the source of truth for the learner's preferences and
  transversal weaknesses; it is read with `profile`.
- `save_graph <concept_id> <path>`: validates the proposal (DAG, known
  documents, known concepts) and stores it. The phase stays `not_started`.
- `save_evaluation <concept_id> <path>`: validates the questions and stores the
  initial evaluation; the phase becomes `initial_evaluation`. Requires the
  phase `not_started`.
- `save_course <concept_id> <path>`: validates the course and stores it.
  Requires the phase `learning`.
- `save_exercise <concept_id> <path>`: validates the question, creates the
  exercise assessment and stores it. Requires the phase `learning`.
- `save_final_exam <concept_id> <path>`: validates the questions and stores the
  final exam; the phase becomes `final_exam`. Requires the phase `learning`.
- `submit_response <concept_id> <path>`: validates the grades the agent
  proposes, records the responses, computes the levels and returns the new
  state. Routes on the current phase: exercise, initial evaluation or final
  exam. Requires an assessment in progress.

Grading
-------
The agent proposes `score`, `assistance_coefficient` and `feedback`; the
backend validates them and computes the level. `activity` returns the question
ids, the prompts, the reference answers and the rubrics, so the agent can
grade what the learner was actually asked.

Validation
----------
The tools reuse the engine's own validators: `orchestration.parse_course`,
`parse_question` and `parse_assessment` check the required fields, the
unit-interval coefficients and the citations. The concept ids must belong to
the stored graph, and the cited documents must be among the graph's source
documents. Invalid input raises and nothing is persisted.

Ordering stays in the backend: `save_course` and `save_exercise` refuse a
concept that is not the next one in `plan_concepts` (or the concept already in
progress) and return the expected concept id.

State
-----
Every write updates `parcours_state` (phase, current_assessment_id,
current_concept_id) and appends a history event. The ids are generated by the
backend (`uuid4`) and returned to the agent, so the agent never invents them.
