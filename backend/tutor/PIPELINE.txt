Pedagogical domain engine
=========================

This module contains pure domain models and calculations. It does not store
learner data, create an interface, generate tests, use SQLite, or call a model.

Concept model and graph
-----------------------

Create each concept as Concept(id, prerequisites=frozenset(), target_level=1.0,
weight=1.0), then pass a mapping from concept id to Concept.

- The target level is in [0, 1]. The weight is finite and non-negative.
- Prerequisite ids must exist in the mapping; each mapping key must match the
  Concept.id.
- topological_order(concepts) validates the graph and returns a deterministic
  order. Missing prerequisites and cycles raise ValueError.

Planning
--------

Call plan_concepts(concepts, current_levels, prerequisite_threshold=0.75).

- current_levels must contain exactly the concept ids, each with a level in
  [0, 1]. The prerequisite threshold defaults to 0.75 and can be overridden.
  This is the prototype's initial operational definition of sufficient mastery;
  it should be reviewed against observed exercise and evaluation results.
- Include every concept whose current level is below its target.
- If a selected concept has a prerequisite below the threshold, add that
  prerequisite even if it has already reached its own target. Apply the same
  check recursively to prerequisites of prerequisites.
- Return a prerequisite-safe topological order. Among concepts currently
  available to work on, prioritize larger concept weight, then larger relevant
  shortfall, then lexicographically smaller id. A prerequisite added only to
  reach the threshold uses its shortfall to that threshold for prioritization.
- Return an empty tuple when no concept is below target or needs prerequisite
  remediation.

Attempts and mastery updates
----------------------------

AttemptType distinguishes EXERCISE, EVALUATION, and FINAL_EXAM. Attempt stores
(kind, score, assistance_coefficient, difficulty_coefficient). The score and
both coefficients are in [0, 1]. The assistance coefficient defaults to 1.0;
lower values represent more substantial assistance. The difficulty coefficient
defaults to 1.0; the tutor should give more difficult and informative exercises
a higher value and easy or weakly discriminating exercises a lower value.
Evaluation and final-exam categories are recorded, but use the same update rule
for now, as requested.

Call update_level(current, result, eta, assistance_coefficient=1.0,
difficulty_coefficient=1.0), or update_level_from_attempt(current, attempt, eta).
Both calculate:

    eta_effective = eta * assistance_coefficient * difficulty_coefficient
    current + eta_effective * (result - current)

The coefficients change how strongly the response updates mastery, not the raw
score. A help coefficient of 0 leaves the level unchanged; larger difficulty
coefficients make the exercise more influential. The backend validates the
level, score, eta, and both coefficients in [0, 1].

Weighted gap and progression
----------------------------

Call weighted_gap(current_levels, target_levels, weights=None).

- Current and target maps must contain exactly the same concept ids; all levels
  must be in [0, 1].
- If omitted, weights default to 1. Otherwise weights must contain exactly the
  same ids and be finite and non-negative.
- The gap is the sum of weight * max(target - current, 0), as defined in the
  specification. It may exceed 1. If all weights are zero, return 0.

Call progression(initial_gap, current_gap) to calculate the clamped fraction of
the original gap closed. Gaps must be finite and non-negative. If the initial
gap is zero, return 1 when the current gap is also zero, otherwise 0.

Typical orchestration
---------------------

For a scored response, create an Attempt with its category and the assistance
and difficulty coefficients estimated by the tutor. Update the associated
concept level with update_level_from_attempt, then recalculate weighted_gap
and progression. Use plan_concepts to obtain the current prerequisite-safe work
order. The web interface in `backend/web/` (see `WEB.txt`) connects this
pipeline to the learner. Persistent learner state, documents, concept graphs
and generated courses are available in
`storage.py` (see `STORAGE.txt`), `documents.py` (see `DOCUMENTS.txt`),
`graph.py` (see `GRAPH.txt`) and `orchestration.py` (see `ORCHESTRATION.txt`),
which drives the nominal flow and delegates generation to the LLM.
